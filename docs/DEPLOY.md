# Deploying Org Chart

One Node service and one Postgres database. The repository ships a Render
Blueprint (`render.yaml`) and a `Dockerfile`, so the same image also runs on
Fly.io, AWS, Azure or GCP.

Nothing here has been created yet: no Render account, no Slack app. Each step
below says who does it.

## What it costs

On Render, roughly 15 USD a month to start: the Starter web service and the
Basic 256 MB Postgres (check Render's pricing page for current numbers). Move
the database up a plan once a few large workspaces are installed.

## 1. Pick the address

Decide the public https origin first, because Slack needs it in the manifest.
Either Render's own (`https://org-chart.onrender.com`, the name may differ) or
your domain (`https://orgchart.yourcompany.com`, added later under the
service's Custom Domains). This is `BASE_URL`.

## 2. Create the Slack app

At https://api.slack.com/apps, **Create New App -> From a manifest**, pick a
development workspace, and paste the output of:

```sh
npm run manifest -- https://your-base-url
```

Then, on the app's **Basic Information** page, copy the Client ID, Client
Secret and Signing Secret. Under **Manage Distribution**, turn on public
distribution so other companies can install it (required for the Slack
Marketplace too).

The manifest asks for:

| Scope | Token | Why |
| --- | --- | --- |
| users:read, users:read.email, users.profile:read, team:read | Bot | Sync names, titles, photos, Manager field, guest status |
| channels:read, groups:read | Bot | Find Slack Connect people in shared channels |
| commands | Bot | `/orgchart` |
| openid, email, profile | User | Sign in with Slack for the chart and admin page |
| im:write, mpim:write | User | DM and group DM from the chart, as the person |
| channels:manage, channels:write.invites, groups:write, groups:write.invites | User | Create a public or private channel from the chart and invite people |
| users.profile:write | User | Optional: fill the "Org chart" link field on every profile (admins only) |

User scopes are never asked for at install. People grant `im:write` and the
channel scopes the first time they start a group DM or channel, and an admin
grants `users.profile:write` only if they turn on the profile link.

## 3. Create the Render services

Render -> **New -> Blueprint**, connect the GitHub repository and pick the
branch. Render reads `render.yaml` and creates:

- `org-chart`, a Docker web service with a health check on `/healthz`. Each
  release first runs `npx prisma migrate deploy`.
- `org-chart-db`, Postgres 16, reachable only from the web service.

It asks for the secret values:

| Variable | Value |
| --- | --- |
| `BASE_URL` | The origin from step 1, no trailing slash |
| `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_SIGNING_SECRET` | From step 2 |

`SLACK_STATE_SECRET` and `TOKEN_ENCRYPTION_KEY` are generated by Render.
Never change `TOKEN_ENCRYPTION_KEY` after the first install, or the stored
Slack tokens can no longer be read and every workspace has to reinstall.

The Blueprint uses the Frankfurt region. Change `region` in `render.yaml`
before the first deploy if most customers are elsewhere; a database cannot
move regions later.

**Row-level security:** the app connects as the database's owner role, which
Render does not make a superuser, and the migrations use `FORCE ROW LEVEL
SECURITY`, so tenant isolation applies. Do not point `DATABASE_URL` at a
superuser on other hosts.

## 4. Install and check

1. Open `BASE_URL` and press **Add to Slack**. The installer becomes the
   workspace's first org chart admin and a full sync starts.
2. In Slack, open the app's **Home** tab: it lists your manager, peers and
   reports, with **Open full chart**.
3. Try `/orgchart`, `/orgchart @someone`, and **View in org chart** from a
   message's ⋮ menu.
4. On the chart, tick two people and press **Group DM**. Slack asks once to
   let Org Chart start conversations for you.
5. Optional, profile link: in Slack's admin settings, add a custom profile
   field of type **Link** named "Org chart". On the chart's admin page,
   Settings, pick the field and press **Connect a Slack admin account** (a
   Slack admin or owner). Every profile then gets its chart link, and new
   people get theirs after the nightly sync.

The app needs Slack Pro or higher: custom profile fields and writing other
people's profiles are paid features.

## Running elsewhere

```sh
docker build -t org-chart .
docker run -p 3000:3000 --env-file .env org-chart
# before each release, against the same database:
docker run --rm --env-file .env org-chart npx prisma migrate deploy
```

## Slack Marketplace

Listing needs a public landing page (the root of `BASE_URL`), a privacy
policy, a support contact, a reason for every scope (the table above) and a
test workspace for Slack's reviewers. Review usually takes several weeks.
